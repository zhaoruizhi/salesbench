# SalesBench-QA 论文与工程优化路线

## 1. 最终研究方案

论文主问题是：当前多模态大模型能否在主播带货短视频中可靠完成 BP、CM、SS、AE 四个层次的内容理解？

互动分析作为额外问题：VQA 错误是否在不同互动快照分层中呈现差异？这项分析不构成 VQA benchmark，不预测因果效果，也不与四任务合并计分。

建议论文题目：

> SalesBench-QA：面向主播带货短视频的证据可追溯多模态问答基准

## 2. 研究问题

- RQ1：四任务定义能否覆盖营销短视频的关键内容理解能力，同时避免互动与转化泄漏？
- RQ2：Evidence-First 标注相较自由 question-first 生成，能否降低无证据回答、重复和冲突？
- RQ3：不同多模态大模型在 BP、CM、SS、AE 上的能力差异和主要错误类型是什么？
- RQ4（额外分析）：模型表现与互动快照之间是否存在描述性关联，且该关联在控制品类、粉丝量、时长和发布时间后是否稳定？

## 3. 论文贡献

1. 四任务主播带货视频 VQA 协议，明确每类可回答与禁止回答边界。
2. EvidenceUnit 到 GroundedAnnotation 再到 QA 的可追溯数据生产方法。
3. 公开模型输入、私有标准答案、Judge 与互动数据之间的严格防火墙。
4. 多模型四任务评测、错误分析和非因果互动诊断。

不要将“真实互动效果预测”写成 benchmark 创新点，也不要声称互动量代表销售或转化。

## 4. 工程优化步骤

### Phase A：协议收敛

- 删除 LightGBM、最终综合分、旧效果预测和旧五任务运行链路。
- 固定 BP/CM/SS/AE 枚举、子类型和 question programs。
- 固定公开输入为 16 帧 + ASR/字幕 + question。
- 固定四任务宏平均为主分数，缺失答案计 0。

验收：CLI、runner、evaluator 均拒绝未知任务；运行源码中不再引用旧任务或效果标签。

### Phase B：EvidenceDataset

- 统一 `EvidenceUnit`、`GroundedAnnotation`、`VideoEvidenceRecord` 契约。
- Evidence Extractor 仅产出 visual/OCR/ASR 事实。
- C1-C6 仅作内部 inventory、候选发现和审计。
- 加入置信度门槛、Challenger、Adjudicator、本地质量规则、语义去重和冲突检查。
- 支持断点续跑、并发和含视频哈希的帧缓存指纹。

验收：证据外键有效率 100%，私有字段泄漏率 0，拒绝项自动入库率 0。

### Phase C：人工复核与编译

- 低置信度、歧义、冲突和无足够证据项进入 `human_review_queue.jsonl`。
- 双人复核核心 test 集，分歧由第三人裁决。
- QA 答案从结构化值确定性渲染，不调用模型生成标准答案。
- 正式发布要求四任务均有样本，并按 creator 做 80/10/10 划分。

验收：所有 QA 均有 `source_annotation_ids` 和 `evidence_refs`；公开文件无答案或私有元数据。

### Phase D：模型评测

- 选择若干闭源与开源 MLLM，在完全相同公开输入下作答。
- 输出统一 `predictions.jsonl`。
- Judge 只见参考答案和直接证据上下文，不见互动量、粉丝量或标题。
- 报告四任务分数、宏平均、微平均、缺失答案和 Judge 失败。

验收：至少一个完整端到端运行；同一输入重复编译完全一致。

### Phase E：互动诊断

- 保存私有 log1p 互动快照与分层变量。
- 做 Spearman、匹配或分层关联分析。
- 对 VQA 诊断切片报告 bootstrap 置信区间。
- 明示非因果、非排行榜、非 benchmark 内容。

验收：互动字段不会进入 Evidence prompt、public QA、模型 prompt 或 Judge prompt。

## 5. 实验矩阵

主实验：

- 模型 × BP/CM/SS/AE；
- overall macro 与 auxiliary micro；
- creator-disjoint test；
- 按问题子类型、证据模态和视频时长分层。

数据质量实验：

- 自动接受与人工接受精度；
- 低置信度进入复核率；
- 重复和冲突过滤率；
- Evidence-First 与历史 question-first 的小规模质量对照。

额外互动实验：

- VQA 分数与互动 profile 的描述性关联；
- 品类、粉丝量、时长、发布时间分层；
- bootstrap 区间与敏感性分析。

## 6. 规模推进门

1. 5 视频：验证契约、提示词、复核格式和完整闭环。
2. 20 视频：检查四任务覆盖、重复率和证据质量。
3. 100 视频：完成人工质量评估、基线和统计区间。
4. 128 视频 alpha：冻结版本并做多模型比较。
5. 是否扩容：只根据覆盖缺口、学习曲线和置信区间决定，不预设 2,000+ 是必要条件。

## 7. 论文结构

1. 绪论：场景、问题、贡献与边界。
2. 相关工作：VideoQA、广告理解、多模态评测、数据标注质量。
3. 数据与任务：数据来源、四任务本体、公开/私有协议。
4. Evidence-First 方法：证据、标注、质疑、裁决、人工复核和 QA 编译。
5. 实验：模型、指标、主结果、消融和质量评估。
6. 互动诊断：数据局限、描述性方法、结果与敏感性分析。
7. 结论与局限：不能从互动快照推断销售因果。

## 8. 当前优先级

- P0：跑 5/20 视频真实生成并进行人工复核。
- P0：冻结四任务数据卡、标注手册和公开提交协议。
- P1：完成 creator-disjoint 划分与多模型 baseline。
- P1：补充 Judge 与人工评分一致性实验。
- P2：运行独立互动诊断并决定是否放入论文正文或附录。

历史 LightGBM、数值最终分和旧 question-first 结果只用于说明研究路线如何收敛，不能与当前 VQA 分数直接比较。
